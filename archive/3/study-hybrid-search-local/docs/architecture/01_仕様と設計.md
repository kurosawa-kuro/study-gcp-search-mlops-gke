# 01_仕様と設計 (Phase 3: 不動産ハイブリッド検索 Local)

> **2026-05-05 更新**: Phase 3 は Wave 1-7 の基礎実装まで接続済み。  
> Docker Compose 上で **Meilisearch + multilingual-e5 + pgvector + RRF + LightGBM LambdaRank** の
> 3 段検索に加え、**行動ログ → labeling → training dataset → 再学習** の最小サイクルを一巡できる。  
> ただし **`pipeline.evaluation_job.main` の hold-out 評価はまだ synthetic split** を使う。

> canonical な Phase 横断仕様は
> [`../../../../7/study-hybrid-search-gke/docs/architecture/01_仕様と設計.md`](../../../../7/study-hybrid-search-gke/docs/architecture/01_仕様と設計.md)。

---

## §0. 位置付け

Phase 3 は **ローカル完結でハイブリッド検索と ML 連動を学ぶための完成形** であり、Phase 4 以降へ足し算する起点でもある。

- ドメインは不動産検索
- 検索は lexical + semantic + rerank の 3 段
- UI は user 画面と developer 補助画面を最小限持つ
- MLOps は local 最小構成で、`ranking_labels` を使った再学習まで通す

Phase 3 で成立していること:

- `/search` が `ranking_log` と event schema の両方へ publish する
- `/feedback` が 5 種 action を `feedback_events` と `user_actions` に記録する
- `make label` が `ranking_labels` を作る
- `make build-training-dataset` が CSV を出す
- `make train` が `ranking_labels` 実データで LightGBM を再学習する
- `make verify-all` が app / ML / workflow contract をまとめて確認する

---

## §1. 中核検索仕様

中核 5 要素は Phase 3 / 4 / 7 で共通:

1. Meilisearch BM25
2. multilingual-e5 encoder
3. ベクトル検索
4. RRF 融合
5. LightGBM LambdaRank rerank

Phase 3 ではこれを Local 実装で構成する。

| 段 | Phase 3 実装 | Port |
|---|---|---|
| Lexical | `MeilisearchLexicalSearch` | `LexicalSearchPort` |
| Query 補助 | `RedisSynonymExpander` | `SynonymExpanderPort` |
| Cache | `RedisSearchCache` | `SearchCachePort` |
| Encoder | `LocalE5Encoder` | `EncoderClient` |
| Vector search | `PgVectorSemanticSearch` | `SemanticSearchPort` |
| Fusion | `rrf_fuse` | service 純粋関数 |
| Rerank | `LocalLightGBMReranker` | `RerankerClient` |

補足:

- `LocalE5Encoder` と `pipeline.data_job.main` は `ml/common/hf_cache.py::resolve_sentence_transformer_source()` を使い、**共有 `hf_cache` の local snapshot を優先**する
- `make warm-model` で multilingual-e5 を先に cache へ入れられる
- `RedisSearchCache` は `search:v1:<hash>` を 60 秒 TTL で保持する

## §3. API 仕様

| メソッド + Path | 役割 |
|---|---|
| `GET /health` | liveness |
| `GET /readyz` | readiness。`search_enabled` / `rerank_enabled` / `model_path` を返す |
| `POST /search` | 3 段検索を実行し、結果を返す |
| `POST /feedback` | 5 種 action を受け、`feedback_events` と `user_actions` へ記録 |
| `GET /model/info` | encoder / reranker / model path 情報 |
| `GET /model/metrics` | developer 用のモデル精度確認 |
| `GET /model/data` | developer 用の data preview |
| `GET /ui/` | user 検索画面 |
| `GET /ui/dev/model/metrics` | developer 画面: モデル精度 |
| `GET /ui/dev/data` | developer 画面: 学習データ |
| `GET /ui/property/{property_id}` | 物件詳細ページ |

`POST /feedback` で受ける action は次の 5 種のみ:

- `click`
- `detail_view`
- `favorite`
- `request_button_click`
- `request_complete`

`inquiry_complete` / `contract` / `bounce` / 長時間滞在は **アプリ経路では扱わず**、labeling job の synthetic 注入対象とする。

## §5. データフロー

### オンライン検索

1. `RedisSearchCache` で cache lookup
2. `RedisSynonymExpander` で lexical 用 query expansion
3. Meilisearch で lexical 候補取得
4. multilingual-e5 + pgvector で semantic 候補取得
5. RRF で融合
6. PostgreSQL から property / feature を補完
7. LightGBM で rerank
8. `ranking_log` と event schema に publish
9. 応答を返し、必要なら cache に保存

### 継続改善サイクル

10. `/feedback` で `user_actions` を蓄積
11. `make label` で `ranking_labels` を UPSERT
12. `make build-training-dataset` で `training_dataset.csv` を生成
13. `make train` で `PostgresRankerRepository` から実データを読んで再学習
14. `make evaluate` で `metrics.json` を更新

注意:

- **trainer は実データ接続済み**
- **evaluation job はまだ synthetic hold-out**

## §7. Port / Adapter 境界

Phase 3 は現状 14 Port を持つ。

- `LexicalSearchPort`
- `SynonymExpanderPort`
- `SearchCachePort`
- `EncoderClient`
- `SemanticSearchPort`
- `RerankerClient`
- `CandidateRetriever`
- `FeatureFetcher`
- `RankingLogPublisher`
- `FeedbackRecorder`
- `EventWriter`
- `EventRepository`
- `LabelRepository`
- `PropertyRepository`

原則:

- Service は Port だけを import する
- adapter は composition root で配線する
- `ml/labeling/` は pure logic を維持し、Phase 4/7 へそのまま流用する
