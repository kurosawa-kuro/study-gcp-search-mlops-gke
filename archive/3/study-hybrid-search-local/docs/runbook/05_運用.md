## 1. PDCA メインフロー

### 1.1 目的

Phase 3 の運用は、**ローカルで速く回しつつ app と ML を一緒に確認する** ことが目的。

基本サイクル:

```text
make warm-model   # 初回だけ推奨
  ↓
make build
  ↓
make up
  ↓
make seed
  ↓
make train
  ↓
make serve-bg && make wait-api
  ↓
/search /feedback /ui/* を確認
  ↓
make label
  ↓
make build-training-dataset
  ↓
必要なら make train
  ↓
make down / make clean
```

### 1.2 初回準備

```bash
make doctor
make sync
make warm-model
make build
```

補足:

- `uv` / `docker` / `docker compose` が前提
- multilingual-e5 は image に焼かず `hf_cache` volume に持つ
- `make warm-model` を先に回すと初回 `seed` と app 起動の体感がかなり良い

### 1.3 1 サイクル実行例

```bash
make up
make seed
make train
make serve-bg
make wait-api

curl -s http://localhost:8000/health
curl -s http://localhost:8000/readyz | jq

curl -s -X POST http://localhost:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"新宿区西新宿 1LDK","filters":{"max_rent":150000},"top_k":5}' | jq

curl -s -X POST http://localhost:8000/feedback \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"<searchのrequest_id>","property_id":"prop-0001","action":"click"}' | jq

make label
make build-training-dataset
make train
```

## 2. Make ターゲットの意味

| target | 役割 |
|---|---|
| `make build` | `build-jobs` + `build-api` |
| `make build-jobs` | shared pipeline image build |
| `make build-api` | search-api image build |
| `make up` | `postgres` / `meilisearch` / `redis` 起動 + `migrate-db` |
| `make migrate-db` | 既存 volume に SQL migration を idempotent 再適用 |
| `make warm-model` | multilingual-e5 を共有 `hf_cache` に事前取得 |
| `make seed` | property / embeddings / feature mart / Meilisearch / Redis 同義語投入 |
| `make seed-synonyms` | Redis 同義語辞書だけ再投入 |
| `make train` | `ranking_labels` 実データで学習。空なら synthetic fallback |
| `make label` | `search_impressions × user_actions → ranking_labels` |
| `make build-training-dataset` | training dataset CSV を `ml/registry/artifacts/datasets/` に出力 |
| `make evaluate` | latest model を評価し `metrics.json` 更新 |
| `make serve` | search-api foreground 起動 |
| `make serve-bg` | search-api background 起動 |
| `make wait-api` | `/health` が 200 になるまで待機 |
| `make verify-contracts` | workflow contract 検証 |
| `make verify-app` | app / API / UI 総合検証 |
| `make verify-ml` | labeling / dataset / retrain / evaluate 総合検証 |
| `make verify-all` | 全体検証 |
| `make down` | volume を残して停止 |
| `make clean` | volume と artifact を削除して完全初期化 |

## 3. 定常運用

### 3.1 見るページ

- `http://localhost:8000/ui/`
  - user 検索画面
- `http://localhost:8000/ui/dev/model/metrics`
  - model metrics
- `http://localhost:8000/ui/dev/data`
  - `feature_mart` / `ranking_labels` / `search_impressions` / training dataset preview
- `http://localhost:8000/docs`
  - Swagger

### 3.2 DB / event schema

最低限見るテーブル:

- `ranking_log`
- `feedback_events`
- `search_events`
- `search_impressions`
- `user_actions`
- `ranking_labels`

例:

```bash
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT COUNT(*) FROM search_impressions;'
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT action_type, COUNT(*) FROM user_actions GROUP BY 1 ORDER BY 1;'
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT label_source, COUNT(*) FROM ranking_labels GROUP BY 1 ORDER BY 1;'
```

### 3.3 artifact

見る場所:

- `ml/registry/artifacts/latest/model.lgb`
- `ml/registry/artifacts/latest/metrics.json`
- `ml/registry/artifacts/datasets/<run_id>/training_dataset.csv`

### 3.4 cache / model 周り

- `search-api` と `seed` は `resolve_sentence_transformer_source()` により `hf_cache` の local snapshot を優先する
- 初回が遅いときは `make warm-model`
- 同義語更新後に結果が古ければ Redis の `search:*` cache を疑う

make verify-all

1. `/ui/` で検索
2. 結果カードから詳細ページへ遷移

## 5. トラブルシューティング

### 5.1 `rerank_enabled=false`

```bash
make train
docker compose up -d --force-recreate search-api
curl -s http://localhost:8000/readyz | jq
```

### 5.2 `ranking_labels` が増えない

```bash
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT COUNT(*) FROM user_actions;'
make label
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT COUNT(*) FROM ranking_labels;'
```

### 5.3 `/ui/dev/data` に training dataset が出ない

```bash
make build-training-dataset
find ml/registry/artifacts/datasets -maxdepth 2 -type f | sort
```

### 5.4 同義語更新後も結果が古い

```bash
make seed-synonyms
docker exec phase3-redis redis-cli --scan --pattern 'search:*' | \
  xargs -r -I{} docker exec phase3-redis redis-cli DEL {}
```

### 5.5 初回モデル取得が遅い

```bash
make warm-model
```

### 5.6 DB を完全に作り直したい

```bash
make clean
make build
make up
make seed
make train
```

## 6. ロールバック / やり直し

### 6.1 search-api だけやり直す

```bash
docker compose up -d --force-recreate search-api
```

### 6.2 DB と artifact をやり直す

```bash
make down
rm -rf ml/registry/artifacts/*
docker compose down --volumes
make up
make seed
make train
```

### 6.3 完全初期化

```bash
make clean
make build
make up
make seed
make train
docker compose up -d search-api
```
