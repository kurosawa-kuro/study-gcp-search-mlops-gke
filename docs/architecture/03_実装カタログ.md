## 3. Runtime / Workflow（実行系の地図）

| flow | target | 目安 | 支配 step | 正本 |
|---|---|---|---|---|
| provision + rollout | `make deploy-all` | 初回 50-72 分 | step 6 `tf-apply`（GKE cluster + Composer Gen3 環境作成 + VVS index deploy。VVS Index/Endpoint が GCP 残置されていれば `terraform import` で no-op 化され短縮、残置 ID が古いと再作成で延びる） | [`05_運用.md`](../runbook/05_運用.md) |
| canonical validation | `make run-all-core` | ~9-15 分（16 step） | `label-build`（~3min）+ `ops-train-wait`（~5min）+ `seed-test` | [`04_検証.md`](../runbook/04_検証.md) |
| teardown | `make destroy-all` | 12-17 分（8 step） | `destroy-main`（GKE + Composer destroy） | [`05_運用.md`](../runbook/05_運用.md) |
| local 検証（GCP 非接触） | `make verify-local-hybrid` / `verify-local-app` / `verify-local-ml` | 数十秒 | — | [`04_検証.md`](../runbook/04_検証.md) |
| local build（5 image） | `make build-all-local` | 数分 | docker buildx | [`04_検証.md`](../runbook/04_検証.md) |

- `run-all-core` の step 順（`scripts/ops/run_all.py::STEPS` が正本、16 step）: `check-layers → seed-test → sync-elasticsearch → ops-livez → ops-search → ops-search-components → ops-vertex-vector-search-smoke → ops-vertex-feature-group → ops-feedback → ops-ranking → ops-label-seed → label-build → ops-train-now → ops-train-wait → ops-daily → ops-accuracy-report`。⚠️ `ops-label-seed`（behavior 投入）+ `label-build`（`ranking_labels` materialize）は `ops-train-now` の**前**（逆順だと初回 deploy 直後は `ranking_labels` が空 → `load_features` が空 frame → `train-reranker` crash、INC-2026-05-11-04）。
- `deploy-all` の step 順（`scripts/setup/deploy_all.py::_steps()` が正本、15 step）: `tf-bootstrap → tf-init → recover-wif → sync-dataform → tf-plan → tf-apply → seed-lgbm-model → seed-test → apply-manifests → sync-elasticsearch → backfill-vvs → trigger-fv-sync → overlay-configmap → composer-deploy-dags → deploy-api`。
- `destroy-all` の step 順（`scripts/setup/destroy_all.py::_steps()`、8 step）: `seed-clean → undeploy-vertex-endpoints → undeploy-vvs-deployed-indexes → state-rm-persistent-vvs → wipe-gcs-buckets → flip-deletion-protection → destroy-kserve（GKE より先に K8s/Helm）→ destroy-main（永続 VVS 除外）`。
- **per-step wall time の自動記録 + ETA**: `deploy-all` / `destroy-all` / `run-all` の各 step 完了時に `logs/step_timings.csv`（gitignore、`flow` カラム付き）へ追記、起動時に過去 run の median から ETA + 重い step トップ3 を表示。共有モジュール `scripts/lib/step_timing.py`（`run-all-core` は bash recipe ではなく Python orchestrator `scripts/ops/run_all.py` 経由）。
- `sync-elasticsearch`: `feature_mart.properties_cleaned` を Elasticsearch `properties` index へ bulk upsert する canonical lexical 経路。
