# 05_運用 — Phase 3 (Local Docker Compose)

> 本書のスコープは **「やる」**。`make build` / `make up` / `make seed` / `make train` /
> `make label` / `make build-training-dataset` / `make serve` / `make verify-all` をどう回すか、日常運用で何を見るか、
> 詰まった時にどう戻すかを扱う。
>
> **「OK か判定する」基準は [`04_検証.md`](./04_検証.md)** に分離している。順序は
> **`04_検証.md` → 本書**。

Phase 3 は Docker Compose 上で完結する local hybrid-search phase。Meilisearch BM25 +
multilingual-e5 + pgvector + RRF + LightGBM LambdaRank に加え、Wave 5-7 では
`search_events` / `search_impressions` / `user_actions` / `ranking_labels` と
training dataset 経路まで持つ。app と ML をまとめて回す基準コマンドは `make verify-all`。

---

## 1. PDCA メインフロー

### 1.1 設計意図

Phase 3 の PDCA は **ローカルで速く回す** ことが主眼。Phase 7 のような GCP deploy はなく、
以下の 1 サイクルを何度も回す:

```text
make build
  ↓
make up
  ↓
make seed
  ↓
make train
  ↓
make serve-bg && make wait-api
  ↓
/search, /feedback, /ui/* を確認
  ↓
make label
  ↓
make build-training-dataset
  ↓
必要なら make train を再実行
  ↓
make down / make clean
```

### 1.2 1 度だけ済ませる準備

```bash
make doctor
make sync
make build
```

補足:

- `uv` / `docker` / `docker compose` が前提
- Hugging Face model は image に焼かず `hf_cache` volume を使う
- `env/secret/credential.yaml` は Phase 3 では必須 secret が少ないが、repo ルールに従って配置する

### 1.3 PDCA 1 サイクル

```bash
# 1. backend 起動
make up

# 2. データ投入
make seed

# 3. 初回学習
make train

# 4. API 起動
make serve-bg
make wait-api

# 5. 疎通確認
curl -s http://localhost:8000/health
curl -s http://localhost:8000/readyz | jq

# 6. 検索・行動ログ
curl -s -X POST http://localhost:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"新宿区西新宿 1LDK","filters":{"max_rent":150000},"top_k":5}' | jq

curl -s -X POST http://localhost:8000/feedback \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"<searchのrequest_id>","property_id":"prop-0001","action":"click"}' | jq

# 7. ラベル化 + 学習データ出力
make label
make build-training-dataset

# 8. 必要なら実データで再学習
make train
```

### 1.4 `make` ターゲットの意味

| target | 役割 |
|---|---|
| `make build` | `search-api` / `seed` / `trainer` / `labeler` / `training-dataset-builder` image build |
| `make up` | `postgres` / `meilisearch` / `redis` 起動 + health wait |
| `make seed` | synthetic property / embedding / feature mart / Meilisearch / Redis synonym 投入 |
| `make seed-synonyms` | Redis synonym 辞書だけ再投入 |
| `make train` | LightGBM model を `ml/registry/artifacts/` に出力 |
| `make label` | `search_impressions × user_actions → ranking_labels` |
| `make build-training-dataset` | training dataset CSV を `ml/registry/artifacts/datasets/` に出力 |
| `make evaluate` | hold-out 評価 |
| `make serve` | `search-api` foreground 起動 |
| `make serve-bg` | `search-api` background 起動 |
| `make wait-api` | `GET /health` が 200 になるまで待機 |
| `make api-dev` | host の `uvicorn --reload` 起動 |
| `make verify-pipeline` | integration E2E |
| `make verify-app` | `/search` `/feedback` `/ui/*` `/model/*` の app 総合検証 |
| `make verify-ml` | `label` → `dataset` → `retrain` → `evaluate` の ML 総合検証 |
| `make verify-all` | 静的検証 + Docker Compose + app + ML の一括検証 |
| `make down` | volume を残して停止 |
| `make clean` | volume と artifact を削除して完全初期化 |

## 2. 定常運用

### 2.1 API / UI

日常的に見るページ:

- `http://localhost:8000/ui/`
  - user search UI
- `http://localhost:8000/ui/dev/model/metrics`
  - `/model/metrics` の可視化
- `http://localhost:8000/ui/dev/data`
  - `feature_mart` / `ranking_labels` / `search_impressions` / `training_dataset` preview
- `http://localhost:8000/docs`
  - Swagger

### 2.2 DB / event schema

最低限見るテーブル:

- `ranking_log`
  - 既存互換の search log
- `feedback_events`
  - legacy action 互換
- `search_events`
  - 検索イベント
- `search_impressions`
  - impression 単位
- `user_actions`
  - 5 種 action
- `ranking_labels`
  - labeling 結果

例:

```bash
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT COUNT(*) FROM search_impressions;'
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT action_type, COUNT(*) FROM user_actions GROUP BY 1 ORDER BY 1;'
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT label_source, COUNT(*) FROM ranking_labels GROUP BY 1 ORDER BY 1;'
```

### 2.3 artifact

見る場所:

- `ml/registry/artifacts/latest/model.lgb`
- `ml/registry/artifacts/latest/metrics.json`
- `ml/registry/artifacts/datasets/<run_id>/training_dataset.csv`

### 2.4 developer data preview を更新したい時

`/ui/dev/data` は以下を表示する:

- `feature_mart_property_features_daily`
- `ranking_labels`
- `search_impressions`
- latest training dataset CSV

更新手順:

```bash
make label
make build-training-dataset
```

## 4. トラブルシューティング

### 4.1 `rerank_enabled=false`

原因:

- `make train` 未実行
- `ml/registry/artifacts/latest/model.lgb` が無い
- `search-api` が古い状態で起動中

対処:

```bash
make train
docker compose up -d --force-recreate search-api
curl -s http://localhost:8000/readyz | jq
```

### 4.2 `ranking_labels` が増えない

原因:

- `/feedback` を叩いていない
- `make label` 未実行
- `user_actions` が空

対処:

```bash
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT COUNT(*) FROM user_actions;'
make label
docker exec phase3-postgres psql -U admin -d hybrid_search -c 'SELECT COUNT(*) FROM ranking_labels;'
```

### 4.3 `/ui/dev/data` に training dataset が出ない

原因:

- `make build-training-dataset` 未実行
- `ml/registry/artifacts/datasets/` が空

対処:

```bash
make build-training-dataset
find ml/registry/artifacts/datasets -maxdepth 2 -type f | sort
```

### 4.4 同義語更新後も検索結果が古い

原因:

- Redis SYN-2 cache が HIT

対処:

```bash
make seed-synonyms
docker exec phase3-redis redis-cli --scan --pattern 'search:*' | \
  xargs -r -I{} docker exec phase3-redis redis-cli DEL {}
```

### 4.5 DB を完全に作り直したい

```bash
make clean
make build
make up
make seed
make train
```

## 5. ロールバック / やり直し

### 5.1 最小ロールバック

- search-api だけやり直す

```bash
docker compose up -d --force-recreate search-api
```

### 5.2 DB と artifact だけやり直す

```bash
make down
rm -rf ml/registry/artifacts/*
docker compose down --volumes
make up
make seed
make train
```

### 5.3 完全初期化

```bash
make clean
make build
make up
make seed
make train
docker compose up -d search-api
```
