## 0. 検証 canonical 定義 (V1-V6)

> 本セクションには「**何を verify するか + どうなったら OK か**」だけを書く。今日通ったか、
> 直近 run_id は何か、という進捗 status は `TASKS.md` や `05_精度評価.md` に寄せる。

### 0.1 V1-V6 検証ゲート定義

| # | 項目 | コマンド | 完了基準 (= OK 判定) |
|---|---|---|---|
| **V1** | 静的品質ゲート | `make check` | `ruff` / `ruff format --check` / `mypy` / `pytest tests/unit` が全 PASS |
| **V2** | レイヤ境界 | `make check-layers` | `app/services/protocols/` や `ml/labeling/` に cloud / SDK / adapter 越境 import が無い |
| **V3** | Local stack build | `make build && make up` | `postgres` / `meilisearch` / `redis` が `healthy`、`make wait-db` が timeout しない |
| **V4** | 検索 serving 成立 | `make seed && make train && make serve-bg && make wait-api` → `curl /readyz` | `search_enabled=true` かつ `rerank_enabled=true`、`model_path` が空でない |
| **V5** | app / API / UI 成立 | `make verify-app` | `/search` `/feedback` `/ui/` `/ui/dev/model/metrics` `/ui/dev/data` が通り、`lexical_rank` / `semantic_rank` / `final_rank` が all non-zero |
| **V6** | Wave 5-7 行動ログ / 学習データ経路 | `make verify-ml` | `user_actions` / `ranking_labels` が増え、`training_dataset.csv` と `metrics.json` が生成される |

### 0.2 Phase 3 の「OK」判定原則

Phase 3 の「OK」は単に `/search` が 200 を返すことではない。最低でも次を満たして初めて OK:

- Meilisearch lexical + pgvector semantic + LightGBM rerank の **3 段検索** が成立している
- Phase 3 固有の **SYN-1 同義語辞書** と **SYN-2 検索キャッシュ** が無効化前提で壊れていない
- `/ui/` だけでなく **`/ui/dev/model/metrics`** と **`/ui/dev/data`** が開ける
- Wave 5-7 で追加した **`search_events` / `search_impressions` / `user_actions` / `ranking_labels`**
  と training dataset 経路が最低限動く

### 0.3 fail 時の分岐

- V1 / V2 が fail: まずローカルコード修正。Docker や DB を疑う前に import 境界・型・unit test を直す
- V3 が fail: `docker compose ps` と `docker compose logs postgres meilisearch redis` を確認
- V4 / V5 が fail: `search-api` の health / model artifact / seed 状態を確認
- V6 が fail: `/feedback` payload、`labeler` job、`training-dataset-builder` job の順で切り分ける

## 1. 検証の考え方

Phase 3 はローカル完結 phase なので、**ローカルで弾けるものは全部ローカルで弾く**。Phase 7 のような
GCP live gate は不要だが、その代わり Docker Compose 4 service + ML artifact + PostgreSQL 永続化まで
含めて確認する。

階層別の責務:

| 層 | 何が確認できる | 所要時間 |
|---|---|---|
| 静的検証 (§2.1) | import / 型 / format / unit test / 層境界 | 10-60 秒 |
| Local stack (§2.2) | Docker Compose 起動、DB/migration、healthcheck | 1-3 分 |
| API / UI (§2.3) | `/search` / `/feedback` / `/model/*` / `/ui/*` の疎通 | 1-5 分 |
| Wave 5-7 (§2.4) | event schema / labeling / training dataset | 1-3 分 |

### 2.3 API / UI 検証

#### L9. health / readyz

```bash
curl -s http://localhost:8000/health
curl -s http://localhost:8000/readyz | jq
```

OK 基準:

- `/health` が `{"status":"ok"}` を返す
- `/readyz` が `status=ready`
- `search_enabled=true`
- `rerank_enabled=true`
- `model_path` が空でない

#### L10. 3 段検索

```bash
curl -s -X POST http://localhost:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"新宿区西新宿 1LDK","filters":{"max_rent":150000},"top_k":5}' | jq
```

OK 基準:

- `results` が空でない
- 各 item の `lexical_rank >= 1`
- 各 item の `semantic_rank >= 1`
- 各 item の `final_rank >= 1`
- 少なくとも 1 件 `score != null`

#### L11. フィードバック / event schema

`/search` レスポンスの `request_id` と実在 `property_id` を使って送る。

```bash
curl -s -X POST http://localhost:8000/feedback \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"<searchのrequest_id>","property_id":"prop-0001","action":"click"}' | jq
```

OK 基準:

- `{"accepted": true}` が返る
- PostgreSQL `user_actions` に 1 row 以上入る
- legacy 互換 action (`click` / `favorite`) の場合は `feedback_events` にも入る

#### L12. developer UI

ブラウザで以下を開く:

- `http://localhost:8000/ui/`
- `http://localhost:8000/ui/dev/model/metrics`
- `http://localhost:8000/ui/dev/data`

OK 基準:

- 3 画面とも 200 で表示される
- `model metrics` は `/model/metrics` のレスポンスを描画できる
- `data` は `/model/data` の table preview を描画できる

### 2.4 Wave 5-7 追加経路

#### L13. labeling

```bash
make label
```

OK 基準:

- `phase3-labeler` が成功終了
- `ranking_labels` テーブルに row が増える
- `label_source` に `no_action` / 実 action / `synthetic_*` のいずれかが入る

#### L14. training dataset

```bash
make build-training-dataset
```

OK 基準:

- `ml/registry/artifacts/datasets/<run_id>/training_dataset.csv` が生成される
- `/ui/dev/data` の `training-dataset` preview に反映される

#### L15. training 実データ経路

```bash

```

OK 基準:

- `ranking_labels` が存在する場合は `pipeline.training_job.main` が `PostgresRankerRepository`
  経由で df を読んで学習する
- `ranking_labels` が空の場合のみ synthetic fallback に入る

### 2.5 integration E2E

```bash
make verify-app
make verify-ml
```

OK 基準:

- `test_pipeline_e2e.py` / `test_app_ui_e2e.py` / `test_ml_feedback_cycle_e2e.py` が全 PASS
- `/health` / `/readyz` / `/search` / `/feedback` / `/ui/dev/model/metrics` / `/ui/dev/data` が通る
- `search_events` / `search_impressions` / `user_actions` / `ranking_labels` と `training_dataset.csv` / `metrics.json` が確認できる

## 3. 退化検知の観点

### 3.1 変更後に疑うポイント

- `pyproject.toml` を触った
  - `uv sync` / Docker build が急に遅くなっていないか
- `composition_root.py` を触った
  - `readyz` で `rerank_enabled` が落ちていないか
- `search_service.py` / `feedback_service.py` を触った
  - `search_impressions` / `user_actions` / `ranking_labels` 経路が切れていないか
- `templates/` / `ui_router.py` / `model_router.py` を触った
  - `/ui/dev/model/metrics` と `/ui/dev/data` が 404 / 500 になっていないか

### 3.2 最低限見るメトリクス

- `/readyz`
  - `rerank_enabled`
  - `model_path`
- `/search`
  - `lexical_rank` / `semantic_rank` / `final_rank`
  - `score`
- PostgreSQL
  - `search_impressions`
  - `user_actions`
  - `ranking_labels`
- file artifact
  - `ml/registry/artifacts/latest/model.lgb`
  - `ml/registry/artifacts/datasets/*/training_dataset.csv`

## 4. 一過性エラーと recovery

| 症状 | よくある原因 | まずやること |
|---|---|---|
| `make up` で postgres health timeout | 旧 volume / 旧 container が壊れている | `docker compose down --volumes` → `make up` |
| `/readyz` で `rerank_enabled=false` | `make train` 未実行 or artifact 未生成 | `make train` を再実行 |
| `/search` が 200 だが `score=null` ばかり | reranker が未ロード | `latest/model.lgb` の有無と `search-api` 再起動を確認 |
| `/feedback` は 200 だが `ranking_labels` が増えない | `make label` 未実行 / action が不足 | `/feedback` 実行後に `make label` |
| `/ui/dev/data` に training dataset が出ない | `make build-training-dataset` 未実行 | dataset builder を実行 |
| 同義語を変えたのに検索結果が古い | SYN-2 cache が HIT している | `search:*` キーを削除するか TTL 待ち |
