system_map — study-gcp-search-mlops-gke

Real-estate hybrid-search API + continuous-retraining MLOps loop on GCP/GKE. Map derived from code (not README aspirations).

1 · Project summary

Purpose

Elasticsearch BM25 + multilingual-e5 + Vertex AI Vector Search are fused via RRF and reranked by a LightGBM LambdaRank model. Behaviour events (3-table Pub/Sub canonical) feed a labeling job → training pipeline → Vertex Model Registry promote, orchestrated by Cloud Composer DAGs.

3 · Main flows

3.1 hybrid_search_request — POST /api/v1/search
External I/O: Elasticsearch · Vertex AI Vector Search · KServe (encoder + reranker) · Vertex AI Feature Online Store · BigQuery · Pub/Sub · Cloud Memorystore (Redis) · BQML
  1. search_router → bind request_id, map SearchRequest → SearchInput, depend on SearchService.
  2. SearchService.search → emit search_event via EventWriter.
  3. KServeEncoder.embed("query: " + query) → 768-dim ME5 vector. Encoder runs on the original (unexpanded) text.
  4. RedisSynonymExpander.expand(query) (opt-in) → expanded lexical query.
  5. run_search: retriever.retrieve(query_text, query_vector, filters, top_k).
  6. BigQueryCandidateRetriever → ElasticsearchLexical.search (top 200) + VertexVectorSearch.search (top 200) → rrf_fuse(K=60) → BQ JOIN on properties_cleaned + property_features_daily.
  7. FeatureOnlineStoreFetcher.fetch (opt-in) → merge fresh ctr / fav_rate / inquiry_rate onto candidates.
  8. build_ranker_features → 10-col matrix in FEATURE_COLS_RANKER order.
  9. KServeReranker.predict (or predict_with_explain for TreeSHAP). Tie-break: lexical_rank, semantic_rank.
  10. PubSubRankingLogPublisher.publish_candidates (failures swallowed, ERROR-logged).
  11. Emit impressions per ranked item via EventWriter; optional BQMLPopularityScorer.score.
  12. Return SearchResponse (items include display-side metadata copied from candidate.property_features).
Failure modes: 503 if encoder/retriever missing · ES/VVS errors propagate · FOS failure → degraded (stale features) · ranking_log publish failure silently logged · popularity scorer failure ignored.
3.2 user_feedback_event — POST /api/v1/feedback
External I/O: Pub/Sub · BigQuery (subscription sink)
  1. feedback_router binds FeedbackRequest.
  2. FeedbackService.record → EventWriter.emit_user_action (→ user-actions Pub/Sub topic → mlops.user_actions).
  3. If action ∈ {click, favorite}: also FeedbackRecorder.record (→ search-feedback → mlops.feedback_events).
  4. Returns accepted=false on publish failure (logged, not raised).
Failure modes: Pub/Sub publish failure → accepted=false; schema drift between Pydantic ActionType and BQ enum could silently drop rows.
3.3 daily_feature_refresh — Composer DAG @ 01:00 JST
External I/O: Dataform · BigQuery · Vertex AI Feature Store · Vertex AI Vector Search
  1. DataformCreateCompilationResultOperator + DataformCreateWorkflowInvocationOperator against repo hybrid-search-cloud @ main.
  2. Dataform: sources → staging → features → monitoring SQL refresh feature_mart.*.
  3. KubernetesPodOperator → scripts.domain.gcp.feature_view_sync (Feature Online Store refresh).
  4. ShortCircuitOperator gates on ENABLE_DAILY_VVS_REFRESH=true.
  5. If enabled: scripts.setup.backfill_vector_search_index --apply.
Failure modes: Dataform failure halts FV sync · FV sync may lag silently under quota · VVS backfill opt-in (default off) → possible divergence from BQ embeddings.
3.4 retrain_orchestration — Composer DAG @ 04:00 JST (canonical)
External I/O: BigQuery · GCS · Vertex AI Pipelines · Vertex AI Model Registry · Vertex AI Endpoints · Cloud Logging
  1. scripts.ops.check_retrain decides should_retrain (feedback rows since last run + NDCG drift + last_run timestamp).
  2. scripts.ops.submit_train_pipeline compiles + submits KFP property-search-train to Vertex AI Pipelines (KFP 2.16; compile at runtime inside Pod to avoid module-level import problem).
  3. Pipeline runs: load_features (BQ JOIN) → train_reranker (LightGBM container) → evaluate (gate on ndcg_at_10 ≥ 0.6) → register_reranker (conditional).
  4. ml.training.trainer.run: LightGBM LambdaRank fit, write artifacts, mlops.training_runs row, upload model.txt + metrics.json to GCS.
  5. register_reranker: Vertex Model Registry upload + Endpoint traffic split (10% default).
  6. scripts.ops.vertex.pipeline_wait blocks until SUCCEEDED.
  7. ShortCircuitOperator on AUTO_PROMOTE=true.
  8. scripts.ops.promote (APPLY=1): alias newest version → production.
Failure modes: Empty ranking_labels → load_features fails (root cause: labeling didn't run / ordering violation in run_all) · Eval gate skip wastes compute · Traffic-split misconfig could 100% to regressed model · AUTO_PROMOTE without human review.
3.5 monitoring_validation — Composer DAG @ 04:30 JST
External I/O: BigQuery · Cloud Monitoring
  1. BigQueryInsertJobOperator runs validate_feature_skew.sql → mlops.validation_results.
  2. BigQueryInsertJobOperator runs validate_model_output_drift.sql → mlops.model_monitoring_alerts.
  3. KubernetesPodOperator → scripts.ops.slo_status (SLO + burn-rate alert check).
Failure modes: SQL path resolution (Composer data dir vs repo fallback — 2026-05-03 incident) · Skew SQL false positives under seasonal shift · SLO decoupled from /metrics service label.
3.6 labeling_pipeline — python -m pipeline.labeling_job.main
External I/O: BigQuery
  1. BigQueryEventRepository.read_impressions / read_user_actions since (now − window_days).
  2. ml.labeling.policy.compute_label per (search_id, property_id): weighted ACTION_WEIGHTS → (relevance, label_source).
  3. BigQueryLabelRepository.write_ranking_labels → mlops.ranking_labels.
Failure modes: Stale window → empty labels → empty training frame · Synthetic injection bypasses user_actions and can mask app-emit regressions.
3.7 property_embedding_refresh — python -m pipeline.data_job.main submit
External I/O: BigQuery · Vertex AI Batch Prediction · Vertex AI Vector Search
  1. load_properties (BQ → properties_cleaned slice, optional full_refresh).
  2. batch_predict_embeddings via Vertex BatchPrediction on ME5.
  3. write_embeddings → feature_mart.property_embeddings.
  4. upsert_vector_search → Vertex VVS index (skip if vector_search_index_resource_name blank — Strangler).
Failure modes: VVS upsert silently skipped if unset · embeddings table and VVS index can diverge (no transactional coupling).
3.8 ranking_log_streaming_aggregation — ml/streaming/pipeline.py (Dataflow)
External I/O: Pub/Sub · Dataflow · BigQuery
  1. Source: ranking-log Pub/Sub topic (one msg per /search candidate).
  2. Beam: 1h tumbling window → group by property_id → (impressions, clicks-synthesized-from-rank==1).
  3. Sink: mlops.ranking_log_hourly_ctr.
Failure modes: Clicks proxied from final_rank==1 = biased CTR (loop-closure risk if used for training) · pipeline restart loses in-flight windows unless checkpointed · BQ schema drift.
3.9 check_retrain_smoke — POST /ops/jobs/check-retrain
External I/O: BigQuery · Pub/Sub
  1. retrain_router resolves RetrainQueries from container.
  2. retrain_policy.evaluate → ShouldRetrain decision.
  3. If true: PubSubPublisher.publish retrain-trigger (best-effort).
Failure modes: Cannibalization with Composer DAG if cron set too aggressively (CLAUDE.md non-negotiable) · publish failure → published=false.
3.10 deploy_all_canonical — make deploy-all (15 steps)
External I/O: Terraform state bucket · GCS · GKE · Artifact Registry · Composer
  1. scripts.setup.deploy_all runs steps in order: tf-bootstrap → tf apply stage A → tf apply stage B → seed-minimal-clean → sync-elasticsearch → composer-deploy-dags → build-all-local → push images → deploy-api → configmap-overlay → kserve models → smoke checks.
  2. Terraform modules provision GKE/Composer/Vertex/Pub/Sub/Dataform/Cloud Domains.
  3. Kustomize overlay applies ES + KServe + Gateway + NetworkPolicies.
  4. scripts.deploy.composer_deploy_dags syncs DAGs + SQLs to Composer GCS.
Failure modes: deploy/destroy callsites are not exercised by make check (5-bug incident in M-Wave8.6) · two-stage tf apply can land in partial-applied state on stage A failure · Composer Gen 3 auto-sets GCP_PROJECT — user-set PROJECT_ID can fail with HTTP 400.

5 · Risks & open questions

Risks

high
Cloud Logging fallback can silently disable the loop. If 3 Pub/Sub topics are unconfigured at startup, CloudLoggingEventWriter is wired and downstream BQ tables stay empty — entire retrain loop degrades to synthetic-only with no obvious surface signal.
high
Streaming CTR is a click-proxy. ml.streaming.pipeline synthesizes click from final_rank==1 instead of joining real /feedback. Hourly CTR is biased — using it for training would close a feedback loop on the model's own ranking.
high
Feature parity 6-locations invariant. Adding a ranker feature requires synchronized edits in Dataform / build_ranker_features / FEATURE_COLS_RANKER / Terraform ranking_log.features / validate_feature_skew.sql / Vertex Feature Group. Drift = training-serving skew.
med
Composer cron cannibalization. Cloud Scheduler still hits /ops/jobs/check-retrain — if reconfigured to a high-frequency cron it would double-fire retrain alongside the Composer DAG (CLAUDE.md non-negotiable).
med
Stub pipelines. pipeline.evaluation_job.main and pipeline.batch_serving_job.main are KFP stubs (del project_id) — compile but do nothing. README implies offline eval is wired.
med
Elasticsearch hardening parked. ECK manifest is intentionally HTTP + anonymous superuser, pinned by a contract test. Becomes prod-grade only if exposed beyond the GKE cluster.
med
Deploy-path coverage gap. make check excludes scripts/setup/* and scripts/domain/* callsites; deploy/destroy bugs only surface during real make deploy-all (5-bug incident in M-Wave8.6).
med
AUTO_PROMOTE gate is a single metric. retrain_orchestration auto-aliases production on AUTO_PROMOTE=true regardless of human review — the only gate is NDCG@10 ≥ threshold.
med
ranking_log publish is best-effort. search_service.run_search swallows publish failures (telemetry). A persistent Pub/Sub / IAM outage would silently void retraining data.
med
action_type schema drift. 8 action_type values must stay aligned across Pydantic / Terraform / labeling YAML / labeling SQL / EventWriter Port / ranking_labels — only enforced by docs + tests, not a generated schema.
low
FOS resource IDs blank → no /search. SearchBuilder.resolve_feature_fetcher fails loud at startup if FOS config is incomplete when enable_search=True.
low
API subprocesses out to bq. /ops/destroy-check / search-volume / runs-recent run subprocess.run inside the FastAPI process — uncharacteristic latency/crash mode for an API.

Open questions

  • Does pipeline.evaluation_job.main get wired before the Wave 5 dashboard goes GA, or does it rely on training_runs only?
  • Are mlops.ranking_log_hourly_ctr rows actually consumed downstream (feature mart? eval?) or is the streaming pipeline orphaned?
  • Is the retrain-trigger Pub/Sub topic subscribed to anything in canonical mode, or is it dead-letter telemetry for the smoke endpoint?
  • ml/serving/adapters/kserve_predictor.py overlaps with app/services/adapters/kserve_*.py — which is canonical for non-app callers?
  • ml/streaming/ports + adapters look like scaffolding (one Dataflow adapter). Useful Port or premature abstraction?
  • scripts/ops/ops_router shells out to bq — migrate to BigQueryMetricsRepository or keep as operator-only shortcut?
